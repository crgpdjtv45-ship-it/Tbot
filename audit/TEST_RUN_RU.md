# Исправления и запуск PAPER-теста · 5 ноября 2026

Сервис запущен в фоне на [http://127.0.0.1:8000](http://127.0.0.1:8000). Режим PAPER: котировки Bybit настоящие, депозит и исполнения виртуальные. Автопилот включён. Реальные биржевые ордера программно заблокированы.

На момент приёмки: ready=true, 5/5 пар со свежими котировками и рассчитанными моделями, balance=10000 USDT, ошибок потока нет. Подходящих по коинтеграции пар нет, открытых и закрытых сделок нет. Для проверки механики сделок использовались изолированные детерминированные данные; сделки в рабочий журнал не подмешивались.

**Исправленный поддерживаемый контур**

- Один PaperEngine для всех entrypoints, веб-API и Telegram-команд; старый автономный веб-движок удалён.
- Авторизация Bearer/HttpOnly cookie, запрет внешних origins для записи, локальный bind по умолчанию. Ввод пары и стороны валидируется; UI использует безопасный DOM/textContent, внешние JS/CDN убраны.
- Полные атомарные SQLite checkpoints: позиции, баланс, журнал, комиссии, funding, флаг паузы, cooldown, настройки. Межпроцессная блокировка исключает двух владельцев журнала.
- Единая остановка сначала запрещает входы. Без свежих цен закрытие сохраняется как pending; при восстановлении потока выполняется один раз. Пауза и позиции переживают рестарт.
- Котировки и модели проверяются на свежесть, свечи — на синхронность/пропуски/валидность. Отсутствующие цены не подменяются демонстрационными или ценами входа.
- Вместо ADF адаптивных остатков используется отдельный Engle–Granger; объёмы соответствуют OLS beta. Модель фиксируется на время открытой сделки.
- Лимиты позиций/капитала, денежные и временные стопы, account drawdown, cooldown и верхний порог Z действуют в одном координаторе.
- График строится по полученным закрытым свечам, фиктивные performance-показатели убраны.
- Исправлены полная агрегация старого SQLite-журнала, закрытие соединений и equity-метрики при отсутствии закрытых сделок. Старый OrderManager сохраняет остаток при отказе закрытия/компенсации; биржевое использование этого legacy-кода запрещено.
- Секреты и старое состояние исключены из текущего отслеживания Git, локальные файлы сохранены. Токен больше не зашит в tunnel_manager и не загружается сервисом из старого config.yaml.

**Оставшиеся границы**

Это старт длительного paper-теста, а не завершённый многосуточный прогон и не подтверждение прибыльности. Старые backtest/research-инструменты ещё не унифицированы с новым runtime, их рейтинги не используются для допуска пар и не подтверждают текущую стратегию. Реальный testnet/live адаптер с fills, идемпотентностью и reconciliation пока не реализован и не испытывался. Funding приблизительный; пропущенные во время выключения settlement не восстанавливаются. TradFi не включены в поддерживаемый набор.

Старый раскрытый Telegram-токен остаётся в истории Git и должен быть отозван пользователем через BotFather. Telegram не подключён к рабочему процессу; после ротации его можно включить через переменные окружения, как описано в README. Секреты не отправлялись, реальные Telegram API не вызывались.

Компьютер должен оставаться включённым, без сна, с интернетом. Автозапуск/автоматический перезапуск процесса после сбоя или перезагрузки ОС не настраивались. Если процесс завершится, его нужно запустить снова; SQLite восстанавливает последнюю завершённую транзакцию. Подробные команды запуска, проверки и остановки находятся в [README](C:/Projects/Tbot/README.md).

Рабочая диагностика на момент приёмки сохранена в [data/acceptance.json](C:/Projects/Tbot/data/acceptance.json). Состояние меняется во время теста; актуальную проверку выполняет `scripts/check-paper.py`.
