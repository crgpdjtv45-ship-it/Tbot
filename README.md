# Tbot · длительный PAPER-тест

Поддерживаемый запуск — **paper trading**: реальные публичные котировки Bybit и виртуальные сделки с начальным капиталом 10 000 USDT. Ключи Bybit не нужны. Отправка биржевых ордеров отключена, включая старый BybitClient. Это не проверенная версия для live/testnet исполнения.

Основной сервис, веб-панель и необязательные Telegram-команды используют один PaperEngine. Данные нового теста лежат в `data/paper.sqlite3`; старая демонстрационная история из configs не импортируется.

## Render

Облачный entrypoint — `python run_cloud.py`, bind `0.0.0.0:$PORT`, версия Python зафиксирована в `.python-version`. Сборка: `pip install -r requirements.lock`.

В Render обязательны `DATABASE_URL` (внутренний URL PostgreSQL) и `TBOT_DASHBOARD_TOKEN` (стабильный токен панели). Без PostgreSQL облачный запуск отказывается использовать временный SQLite. `TBOT_START_PAUSED=1` создаёт новый журнал на паузе; сохранённое состояние после рестарта имеет приоритет. Локальные token/config-файлы и Render API key в Git не попадают.

PostgreSQL хранит полный checkpoint; session advisory lock допускает только одного владельца. Во время rolling deploy новый экземпляр сначала обслуживает healthcheck в ожидании, а после завершения старого получает lock, перечитывает последний checkpoint и запускает workers. Управление и запись на ожидающем экземпляре запрещены. Потеря соединения БД запрещает дальнейшую запись/торговлю до восстановления процесса.

Приложение размещено во Frankfurt: [tbot-statarb-paper.onrender.com](https://tbot-statarb-paper.onrender.com). Из исходного региона Oregon Bybit возвращал HTTP 403. PostgreSQL `tbot-paper-journal` сохраняет созданный журнал в Oregon; соединение из Frankfurt использует TLS, внешний доступ разрешён только исходящим диапазонам Render этого региона. Срок бесплатной базы — **до 5 декабря 2026**. Free web service засыпает после 15 минут без входящего трафика; для непрерывного круглосуточного прогона нужен подходящий always-on тариф. Самопинги и автоматическое изменение платного тарифа не настраиваются.

На Render журнал находится в PostgreSQL, а файлы логов — временные; используйте Render Logs. Для входа в панель используется тот же токен из локального `data/dashboard.token`, скопированный в переменную окружения Render. Работа бота от локального компьютера не зависит.

Проверка облачного сервиса:

```powershell
.\.venv\Scripts\python.exe scripts/check-paper.py --url https://tbot-statarb-paper.onrender.com
```

Автодеплой тестового экземпляра отключён; новые коммиты разворачиваются вручную через Render. Исходный сервис в Oregon приостановлен, чтобы не держать второго владельца журнала.

## Запуск на Windows

Из корня проекта, в существующем окружении:

```powershell
.\.venv\Scripts\python.exe run_webapp.py
```

Для запуска в фоне без окна:

```powershell
.\scripts\start-paper.ps1
```

Панель: [http://127.0.0.1:8000](http://127.0.0.1:8000). Для входа скопируйте значение из `data/dashboard.token`. Не отправляйте токен в чат и не публикуйте. После входа используется HttpOnly SameSite cookie на 12 часов; браузерные хранилища токен не сохраняют. По умолчанию сервис доступен только на этом компьютере.

`main.py` и `run_cloud.py` запускают тот же сервис. Параметры: `--host`, `--port`, `--data-dir`. Для облачного размещения необходимы постоянный диск для data, HTTPS, один экземпляр сервиса и настроенная защита доступа. Публичный туннель для локального теста не нужен.

Проверка состояния без раскрытия токена:

```powershell
.\.venv\Scripts\python.exe scripts/check-paper.py
```

Код выхода 0 означает готовность данных и моделей, 2 — прогрев/неготовность. `/healthz` проверяет доступность процесса, защищённый `/readyz` возвращает 503 при неготовности. Готовность процесса не означает наличие подходящей пары или прибыльность стратегии.

## Условия теста

- 5 круглосуточных криптопар: BTC/ETH, ETH/SOL, SOL/AVAX, NEAR/RENDER, ARB/OP. TradFi исключены из тестового набора до проверки календарей и доступности инструментов.
- Котировки обновляются раз в 5 секунд, модели — раз в 5 минут, по 400 часовым свечам. Текущая незакрытая свеча исключается.
- Коинтеграция проверяется Engle–Granger на обучающей части; OLS-хедж фиксируется, последние 48 свечей используются для калибровки Z. Фильтр Калмана не используется как доказательство коинтеграции.
- Вход при `2 <= |Z| < 3.8`, положительном beta, p-value < 0.05 и подходящем half-life. Количества соответствуют ценовому хеджу beta. Модель открытой позиции сохраняется и не меняется при следующем сканировании.
- До 2 пар, по 15% equity на пару, leverage=1. Учтены комиссии 0.055% и оценка проскальзывания 0.05% при входе и выходе. Финансирование оценивается по последней наблюдаемой ставке/расписанию; пропущенные во время выключения расчёты не восстанавливаются. Полной эмуляции ликвидности и биржевых fills нет.
- Выход по возврату Z, статистическому стопу, потере 2% капитала пары или удержанию 36 часов. Просадка equity от максимума на 10% останавливает автопилот и запрашивает закрытие всех позиций. Между сделками пары — 10 минут.
- Нет входов по устаревшим ценам или модели. При исчезновении цен отображается stale; закрытие ожидает свежих котировок и не создаёт результат по выдуманной цене.
- Если фильтр не пропускает пары, бот наблюдает без сделок. Не ослабляйте фильтры только ради появления сделок.

## Пауза, остановка и восстановление

**«Пауза новых входов»** запрещает новые сделки, продолжая сопровождение открытых. **«Стоп и закрытие всех позиций»** сначала блокирует входы, затем закрывает позиции; без свежих цен сохраняет pending-запрос до их появления.

То же через PowerShell:

```powershell
.\scripts\stop-paper.ps1
```

Чтобы после закрытия позиций завершить процесс:

```powershell
.\scripts\stop-paper.ps1 -Terminate
```

Скрипт откажется завершать процесс, если закрытия ожидают котировок, и проверяет, что порт принадлежит нужному entrypoint. Запуск после стопа сохраняет паузу: возобновить можно кнопкой панели. Позиции, fees/funding, полный журнал, баланс, cooldown и настройки восстанавливаются из SQLite. После аварийного завершения используется последняя завершённая транзакция; до свежих данных входы запрещены. Второй процесс с той же БД не запускается.

Логи: `data/paper.log` с ротацией; `data/stdout.log` и `data/stderr.log` при фоновом запуске. Сохраняйте каталог data; не копируйте работающую SQLite БД без WAL/backup API. Полный журнал не ограничен последними 50 сделками — это лимит отображения.

Для ночного теста компьютер должен оставаться включённым, без сна, с интернетом. Автозапуск после перезагрузки ОС не настроен. При долгой недоступности котировок paper-стоп тоже не может получить достоверную цену исполнения.

## Telegram

Старый раскрытый токен удалён из кода и не используется сервисом. **Сначала перевыпустите его через BotFather**: удаление из исходников не отзывает токен и не убирает старые коммиты Git.

После ротации можно перед запуском установить `TBOT_TELEGRAM_TOKEN` и `TBOT_TELEGRAM_CHAT_ID` в окружении процесса. Команды `/status`, `/trades`, `/stop`, `/resume` используют тот же PaperEngine и доступны только заданному chat_id. Автоматические сообщения при старте/сделках не отправляются. Интеграция проверена без обращений к реальному Telegram; новый токен здесь не настраивался.

## Установка и проверки

Проверенное окружение: Windows, Python 3.11.17. Установленные версии зафиксированы в `requirements.lock`. При наличии uv:

```powershell
uv venv --python 3.11 .venv
uv pip sync --python .venv/Scripts/python.exe requirements.lock
.\.venv\Scripts\python.exe -m pytest -q
uv pip check --python .venv/Scripts/python.exe
```

Lock отражает проверенное Windows-окружение; перенос на другую ОС требует отдельной проверки. Старые research/backtest-скрипты остаются исследовательскими инструментами и не подтверждают результаты текущего paper-движка. Исторические рекламные показатели доходности удалены. `audit/AUDIT_RU.md` описывает исходное состояние до исправлений; `audit/reproduce.py` — исторический диагностический материал, актуальные regression tests находятся в tests.

До включения биржевых ордеров ещё нужны отдельный адаптер исполнения, подтверждение fills/частичных исполнений, идемпотентные orderLinkId, reduceOnly, reconciliation с биржей и испытания отказов на testnet. PAPER-тест проверяет сигналы, процесс и виртуальный учёт, а не эти биржевые механизмы.
